Kitten warm reply latency on Anvil / Raspberry Pi 4
2026-10-20 - ongoing performance work

The AArch64 INT8 matrix runtime can optionally retain immutable weights in
16-column blocks. Call PmI8PackReset with caller-owned memory, then
PmI8PackWeight(source, K, N, wide) while inference is idle. The source weights
and packed arena must remain alive and unchanged. Reset(0,0) disables the
cache. Missing entries use the original layout; incomplete column tails also
use the original weights. No arithmetic, activation quantization, reduction
order or scaling order changes. This is a tensor layout cache, not an audio
cache. The API reports insufficient capacity rather than writing beyond it.

Real Pi tests compared original and packed layouts with four cores. Six large
cases used M=32/65/128, K=768, N=2048, narrow and wide INT8 weights. Four more
covered odd M=33/65, K=17/9 and N=35/17. All output words matched and destination
guards remained intact. Large cases improved approximately 2.6-3.6 times.
Splitting those original matrices by columns was slower and was not selected.

A warm resident Kitten test kept a moving map and Anvil A2DP running. Six fresh
requests ranged from a short greeting to longer road instructions. An initial
packed-weight/opening-window experiment reduced transmitted speech onset from
1.36-2.57 seconds to 1.09-2.17 seconds. Both runs had zero audio underruns,
Bluetooth, graphics and parallel faults. The first request after load was
1.96 seconds in the baseline and 1.56 seconds in the experiment. These are
stream timestamps, excluding speaker acoustic latency. Model weights stayed
resident; no prerecorded waveform was reused. The 0.5-1 second objective is
not achieved across these phrases. Smaller opening-window trials are pending
route/audio validation; do not substitute an isolated kernel gain for the
measured reply latency.

Further exact layout optimization: consecutive axis-group rotations are now
collapsed to a matrix transpose, including NCHW/NHWC transformations. Six real
Pi cases matched the preceding generic implementation word for word: odd 2D,
both 4D rotations, a 3D rotation, a nonmatching permutation using fallback,
and an empty tensor. Two 102,912-word cases improved from 10.8/10.7 ms to
0.34/0.31 ms. Whole reply impact is still being measured. The 48-frame opening
with a 0.5-second lead failed the recorded route with 128 underruns and was
rejected. Retain the validated 64-frame opening and 0.6-second lead.

Exact AArch64 layer normalization now keeps sequential mean/variance reduction
order while normalizing four independent output values per vector, using
separate subtraction/multiply/add operations. Twenty-two real Pi cases matched
all output, mean and inverse-standard-deviation bits with intact guards.
Widths1/3/4/7/768/1025, bias present/absent, constant rows, zero epsilon, large
values, infinities and NaN payloads were covered. The larger single-core cases
improved from8.6-12.9ms to0.26-0.37ms. Existing row parallelism remains enabled.
These are isolated kernel results; whole reply latency validation continues.

Equal contiguous FLOAT MatMul batches now distribute independent attention
heads across four cores, each with private packing scratch. The exact existing
matrix kernel is reused; broadcasting, mixed ranks, small columns and INT8
weights keep their previous dispatch. Scratch is released before inference
returns to its cooperative scheduler. Seven real Pi wrapper comparisons covered
equal rank-four and rank-three batches, uneven head counts, broadcast and
mixed-rank fallback, small columns and zero reduction. Every output word and
shape matched, with balanced scratch accounting. Eligible examples improved
from 0.43/0.81/0.12 ms to 0.23/0.47/0.05 ms. The subsequent six-reply run had
zero underruns; warm short onsets were 0.999/1.012/0.982 seconds. This is a
modest whole-request improvement rather than the isolated kernel speedup.

With packed weights, grouped transpose, exact layer normalization and a
56-frame opening followed by64 frames, three warm short requests reached the
Bluetooth stream in0.994/1.020/0.982seconds. Longer two phrases took1.393/1.466
seconds; the first greeting after load took1.495seconds. All six completed
without underruns while the map moved. A separate actual route recording
completed eight cues with zero underruns and3400 map frames. Keep the0.6second
PCM lead; reducing the lead with repeated32-frame windows had failed earlier.
The reply target is still not met for longer instructions, and acoustic latency
inside the speaker is additional to these transmitted stream measurements.

A subsequent 52-frame opening followed by64 retained the0.6second PCM guard.
Warm short stream onsets were0.925/0.953/0.915seconds; longer two phrases were
1.321/1.387seconds. The first greeting after load took1.415seconds. All six
completed without underruns or fault flags while2480mapframes were rendered.
An actual route with this schedule completed eight cues and3439mapframes,
also with zero underruns and faults. Road-name instructions in that route
still took1.24-2.12seconds to start. A universal subsecond claim is not supported.

An evening replay sounded clear with complete instruction beginnings, but

Raising map updates from12 to30persecond alone increased the underrun count

Uniform random generation now computes four independent Threefry counters
per vector and applies the same separate FP32 conversion, multiply and add
steps.18 real Pi comparisons covered empty and odd tails, seeds, requests,
counter wrap, subnormal bounds, overflow, infinities and NaN payloads. All
output bits and guards matched.65537 draws improved7.87ms to2.67ms and262144
draws31.46ms to10.70ms on one core; this gain applies to uniform draws.

PmRandomRangeParallel also exposes bounded independent counter ranges for
uniform and normal draws, with all parallel work complete on return. It
rejects ranges outside the32-bit counter domain.16 real Pi cases compared
8192-element slices with whole-range output, including both distributions,
seeds, nonzero offsets, request variation, odd tails and NaN bounds. All
output bits and guards matched with four-core dispatch enabled. The normal
transform is unchanged; slicing allows an application to yield between
complete jobs rather than waiting for the entire noise tensor.

Exact AArch64 one-dimensional resize now computes four independent output
coordinates and interpolations per vector, with separate FP32 operations in
the reference order. Twenty real Pi comparisons matched every output bit and
both guards: nearest/linear, asymmetric/half-pixel, up/downsampling, odd widths,
multiple rows, signed zero, infinities and NaN payloads. The large 120021-output
cases improved from15.7-22.7ms to0.555-0.966ms on one core. Unsupported sizes,
coordinates, scales or overlapping buffers retain the reference fallback.
Existing row parallelism is retained.

The subsequent moving-map30FPS experiment still counted2834 inserted silent

This resize improvement does not establish sufficient whole-application audio
